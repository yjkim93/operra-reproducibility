Hands-on: Dynamic Reporting with Python

Author

Peter Degen

This hands-on requires Python and Quarto. Visit the instructions page to learn how to use them in a GitHub codespace.

Create a new Quarto file

  1. In VS Code, create a new file with the .qmd extension
  2. Click on the button Preview on the top right corner of the editor or use the shortcut Ctrl + Shift + K to render a preview of the document
  3. An .html file with the same name as your .qmd file should have been generated

🎉 Congratulations, you have generated your first dynamic report! 🎊

We will now modify the report with our own content.

Editing the YAML header

The YAML1 header delimited by (---) specifies options and metadata of your report. Add information about author and date (use last-modified to always display the latest date) and define the output format as html. Be careful with indentation, YAML is sensitive to spacing! The header can be kept simple or it can contain a lot of information. An example:

---
title: "Title of the report"
subtitle: "Subtitle"
date: last-modified # display the date of the last edit
author:
  - name: "Author 1"
    orcid: 1234-1234-1234-12345
    affiliation: "University of Zurich"
format:
  html:
    toc: true # add a table of contents
engine: jupyter
---

Optional exercise

  • Also add your email and affiliation

Re-render your report to see the changes you just made.

Optional exercise

  • Try rendering the report as pdf instead of html. To do this, add pdf: default in the YAML header under format: at the same indentation level as html:.
Render often

When working on a dynamic report it is recommended to re-render the report often. This allows us to quickly spot errors and fix them on the fly. A useful keyboard shortcut for rendering is Ctrl+Shift+K (or CMD+Shift+K on Mac).

Editing the report content

The two most important elements of a dynamic report are text and code.

Text

Quarto uses Markdown syntax to structure and format text. For example,

# This is a title

Two stars will render a word **bold**.

We can also create lists:

- Element 1
- Element 2

A useful link is this [Markdown guide](https://quarto.org/docs/authoring/markdown-basics.html)

> An impressive quote

This type of text editing is different from WYSIWYG (What you see is what you get) editors, such as Microsoft Word. In VS Code, rendering a .qmd file creates a new window next to your source code that shows a preview of the formatted document and provides a WYSIWYG-like interface.

Code chunks

Code chunks contain executable code and let you embed results directly into your text (e.g., data summaries, plots, or tables). Code chunks are automatically re-run when the document is rendered. If any code chunk fails, the entire document may fail to render. This encourages writing reproducible, error-free code.

Code chunk options

Code chunks are delimited by ```{python} (you can specify other languages like R, Julia, ObservableJS). For each code you can add chunk options to the code chunks with #|, for example #| echo: false will hide the code. In VS Code you can see the options available if you type #| (note the whitespace) and then press Ctrl + Space. Many options can be set globally for the entire document on the YAML header (e.g., under execute:, under html:, or under pdf:).

Load libraries

We first load all Python packages that we will use in our analysis. Copy the code below inside a code chunk.

import pandas as pd # data wrangling
import itables # nicer tables
import matplotlib.pyplot as plt # plotting
import seaborn as sns # nicer plots

sns.set() # activate seaborn defaults
itables.options.allow_html = True # needed to hide index with itables

Read the data

For this example we will use the data set “Vornamen neugeborener Mädchen und Knaben mit Wohnsitz in der Stadt Zürich” (https://data.stadt-zuerich.ch/dataset/bev_vornamen_baby_od3700). This data set contains the names of newborns in the city of Zurich since the year 1993. The data was kindly made available to the public domain via a CCZero license by Open Data Zürich. We will now import the data and rename the variables into English.

url = "https://data.stadt-zuerich.ch/dataset/bev_vornamen_baby_od3700/download/BEV370OD3700.csv"
dat = pd.read_csv(url)
datclean = dat.rename({
  "StichtagDatJahr": "year",
  "Vorname": "name",
  "SexLang": "sex",
  "AnzGebuWir": "births"
  }, axis=1)
datclean.replace({"sex": {"weiblich": "female", "männlich": "male"}}, inplace=True)
Hide warnings in output

You can hide all Python warnings from the output by adding the following to your YAML header:

execute:
  warning: false

Plot the data

Creating a plot in a code chunk automatically inserts it into the rendered Quarto report. For example, we may want to plot the most common names between 2021 and 2025.

# The upper bound is deliberate: the data set gains a year of records over
# time, and bounding the window keeps this figure matching its caption.
top10 = (
    datclean.loc[(datclean["year"] >= 2021) & (datclean["year"] <= 2025)]
    .groupby(["sex", "name"], as_index=False)["births"]
    .sum()
    .sort_values(["sex", "births"], ascending=[True, False])
)
birth_rank = top10.groupby("sex")["births"].rank(method="min", ascending=False)
top10 = top10.loc[birth_rank <= 10]

g = sns.FacetGrid(top10, col="sex", sharex=False, sharey=False, height=5, aspect=0.75)
g.map_dataframe(sns.barplot, y="name", x="births")

# Add bar labels
for ax in g.axes[0]:
  ax.bar_label(ax.containers[0], fontsize=10, padding=-15, color="white")

g.set_axis_labels("Births", "Name")
g.set_titles(col_template="{col_name}")
g.fig.subplots_adjust(top=0.85)
plt.tight_layout()

Note that we can add chunk options to create a caption (#| fig-cap: "Most common names of Zurich newborns in 2021-2025.") and a label (#| label: fig-names). We can then refer to Figure 1 in the text using [@fig-names].

Reproducibility

When creating dynamic reports, it is good practice to document the software versions and other parts of the computational environment. In reports that use the R programming language, a simple yet effective way to document your computational environment is to include the output of sessionInfo(). While there is no built-in equivalent in Python, several workarounds exist. For example, the session-info package provides similar functionality to R’s sessionInfo(). Alternatively, you can also print the installed packages using a command from your Python package manager, for example, !pip freeze or !conda list (the ! is used to execute shell commands directly from a Python chunk in a Quarto notebook). Yet another option is to manually print the computational environment using only the Python Standard Library:

import sys
import platform
import importlib.metadata as metadata

print("Python version:", sys.version)
print("Platform:", platform.platform())
print("\nInstalled packages:")

for dist in sorted(metadata.distributions(), key=lambda d: d.metadata["Name"].lower()):
    name = dist.metadata["Name"]
    version = dist.version
    print(f"  {name}=={version}")

Bonus content

Inline code

A “killer-feature” of dynamic reporting is the possibility to add inline code. This allows us to dynamically insert data summaries into text, avoiding tedious and error-prone copy-and-pasting. For example,

In 2023, the most common male name was `{python} summaries.query("year == 2023 and sex == 'male'").name.iloc[0]` whereas the most common female name was `{python} summaries.query("year == 2023 and sex == 'female'").name.iloc[0]`.

produces

In 2023, the most common male name was Leo whereas the most common female name was Sofia.

Note that, instead of performing computations within an inline code chunk, it is often advisable to perform computations in a separate code chunk, save the results to a variable, and then print the variable in the inline code chunk.

References

In Quarto, it is also possible to include a bibliography file in BibTeX format (with .bib file extension) to automatically generate citations and a bibliography (https://quarto.org/docs/authoring/citations.html). This file has to be specified in the YAML header. In this hands-on, we have a references.bib file in the same directory as this .qmd file, so we specify:

bibliography: references.bib

We can then use [@Hofmann2023] (with parentheses) or @Hofmann2023 (without parentheses) to cite a bibliography item named Hofmann2023. For example, Hofmann et al. (2023) provides an introduction to dynamic reporting. Peikert and Brandmaier (2021) summarizes a more advanced dynamic reporting workflow. Knuth (1984) proposed the literate programming paradigm.

A typical entry from a BibTeX bibliography file looks like this:

@article{Knuth1984,
  title = {Literate Programming},
  volume = {27},
  DOI = {10.1093/comjnl/27.2.97},
  number = {2},
  journal = {The Computer Journal},
  author = {Knuth,  D. E.},
  year = {1984},
  pages = {97--111}
}

These files can either be created manually or with a reference manager (e.g., Zotero).

Practical tips

This concludes a first introduction to dynamic reporting with Quarto. Here are some further tips

  • Nobody knows all the options by heart, use the Quarto documentation!
  • Re-render your reports often to spot errors quickly
  • Use relative paths so that others can reproduce your report
  • Always include the computational environment at the bottom of your report to show details on the computational environment (e.g., package versions) used to generate your report
